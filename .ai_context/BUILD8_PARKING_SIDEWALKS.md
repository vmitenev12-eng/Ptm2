# Сборка 8: парковка, механизм правок PtmFixes, тротуары из миниблоков

## Механизм правок PtmFixes.java при сборке
`PtmFixes.java` (около 470 КБ) слишком велик для редактирования через API, поэтому мелкие правки делаются скриптом `tools/patch_fixes.py` при сборке (`build.yml`, шаг «Prepare Gradle project», сразу после копирования PtmFixes.java в проект Gradle). Список `PATCHES` = (описание, что заменить, на что); каждый фрагмент должен встречаться в файле ровно один раз, иначе сборка падает. Исходный `PtmFixes.java` в корне репозитория этими правками НЕ меняется — при чтении кода помнить, что собирается версия с патчами.

Текущие патчи:
1. Парковка: `double at0 = through ? len / 2.0D : Math.max(0.0D, len - 2.2D);` -> `(through || len <= cfgNum("spotcenterlen", 9.0D)) ? len / 2.0D : ...`. То есть место стоянки на полосе длиной до 9 блоков (и сквозные места) теперь по центру полосы (между первой и второй двойной стрелкой). Раньше у тупиковых полос стоянка была в 2.2 блока до конца полосы (`getSpots`, строка ~5055). Причина жалобы владельца («паркуются относительно первой стрелки, а не между первой и второй») до конца не подтверждена: возможно ещё влияет `busy`-ветка в `parkPhysical` (машина остаётся там, где остановилась, если место занято). Ключ конфига `spotcenterlen` (блоков).

## Тротуары из миниблоков (старая проблема, не решена)
Симптом (по первым описаниям владельца): тротуарные блоки визуально пропадают, если редактировать блок через миниблоки (Little Hammer). Причина не найдена, точное описание симптома нужно уточнить. Что известно по коду:
- `SidewalkBlock` — обычный блок с моделью (`RenderShape.MODEL`), свойства `facing`, `shape` (0..8, форма бордюра зависит от соседей, пересчитывается в `m_6861_`), `condition`; `noOcclusion`; модели из нескольких перекрывающихся элементов без `cullface`.
- LittleTiles считает блок без окклюзии «полупрозрачным»: `ILittleMCBlock.isTranslucent(block) = !isSolid || !canOcclude` — для тротуаров это true, что влияет на отсечение граней между частями (`BERenderManager`, строка ~274) и, возможно, на слой отрисовки.
- Состояние блока в части LittleTiles замораживается (форма `shape` больше не пересчитывается по соседям).
Гипотезы: (а) полупрозрачный слой LittleTiles + gl4es (Pojav) даёт невидимые части; (б) грани отсекаются между соседними частями; (в) заморозка `shape`/`facing` даёт неверную модель.
Нужно от владельца: что именно видно (дыра до земли / фиолетовая заглушка / только верх пропадает), все ли виды тротуаров (asphalt, brick, panel, quartz, stone, плиты), до и после правки.
